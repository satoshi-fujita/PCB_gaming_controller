# 初回実装 設計（design.md）

`docs/product-requirements.md`「10. 未決事項」および`docs/functional-design.md`「8. 未決事項」で保留していた項目を、ここで具体的な数値・方式として確定する。数値は初回実装時点の暫定値であり、実機プレイテストの結果に応じて`DifficultyConfig`内の定数のみを調整すれば良いように設計する。

## 1. 実装アプローチ

- `docs/repository-structure.md`の`src/`構成に沿って、コンポーネントを1クラス1組の`.h`/`.cpp`として追加していく
- 既存の`main.cpp`のタッチ読み取り・キャリブレーション処理を`InputManager`に移設し、`GUI`の描画処理を状態別メソッドに分割する形でリファクタリングする（ゼロから作り直さない）
- `loop()`は「①`InputManager`で入力取得 → ②`GameStateMachine`が現在状態に応じてロジック更新 → ③`GUI`が現在状態を描画」の3ステップに固定する
- 状態遷移・ゲームロジック（`Player`, `WallManager`, `CollisionChecker`）はハードウェアAPI（`M5.Lcd`, `touchRead()`）に直接依存させず、`InputManager`が生成した「上/下/左/右/OK/キャンセルの論理入力」だけを受け取る形にする（`docs/development-guidelines.md`のテスト規約に対応）

## 2. 変更するコンポーネント

`docs/repository-structure.md`で定義した全コンポーネントを新規作成する。既存ファイルの扱いは以下の通り。

| ファイル | 扱い |
|---|---|
| `main.cpp` | 書き換え（オーケストレーションのみに整理） |
| `GUI.h` / `GUI.cpp` | 拡張（状態別描画メソッドを追加、既存の円描画デモコードは削除） |
| その他（`InputManager`, `GameStateMachine`, `SettingsStore`, `DifficultyConfig`, `Player`, `Wall`, `WallManager`, `CollisionChecker`） | 新規作成 |

## 3. データ構造・パラメータの確定

### 3.1 タッチしきい値3段階（`SensitivitySetting`）

キャリブレーション基準値からの変化量（delta）がこの値以上になったら「入力あり」と判定する。値が小さいほど軽いタッチで反応する＝感度が高い。

| 設定 | delta閾値 | 意味 |
|---|---|---|
| 弱（LOW） | 30000 | 反応しにくい。しっかり触れないと入力にならない |
| 中（MID）※デフォルト | 15000 | 標準 |
| 強（HIGH） | 6000 | 反応しやすい。軽く触れただけで入力になる |

### 3.2 自機の可動範囲・当たり判定

- 自機は円として描画するが、当たり判定は計算を軽くするため**矩形（正方形のバウンディングボックス）**で行う（`docs/functional-design.md`未決事項への回答）
- 可動範囲: x = 12〜32（画面左側に固定的なエリア。壁は常にこのエリアより右側に出現する）、y = `playerSize`〜`128 - playerSize`
- 十字キー入力1回（1ループ）あたりの移動量: 2px

### 3.3 壁のスクロール速度

- 固定速度: 1ループ（tick）あたり2px、プレイ中のtick周期は`docs/architecture.md`のパフォーマンス要件に従い30msとする（約66px/秒相当）
- 経過時間によるスクロール加速は行わない（難易度は開口・出現間隔の縮小のみで表現し、パラメータを単純に保つ）

### 3.4 難易度レベル1〜3（`DifficultyConfig`）

| パラメータ | レベル1（易しい） | レベル2（標準） | レベル3（難しい） |
|---|---|---|---|
| 自機サイズ（半径換算のバウンディングボックス辺長） | 10px | 14px | 18px |
| 壁の開口 初期値 | 44px | 38px | 34px |
| 壁の開口 下限値 | 26px | 22px | 18px |
| 開口の縮小レート | 0.3px/秒 | 0.5px/秒 | 0.8px/秒 |
| 壁の出現間隔 初期値 | 1350ms | 1150ms | 950ms |
| 壁の出現間隔 下限値 | 700ms | 600ms | 500ms |
| 出現間隔の縮小レート | 5ms/秒 | 8ms/秒 | 12ms/秒 |

壁の厚み（1本あたりの横幅）は共通で10pxとする。

### 3.5 物理ボタン（GPIO38/39）の配線方式

- 内蔵プルアップ（`INPUT_PULLUP`）を使用し、ボタン押下時は**LOW**として扱う（タクトスイッチの片側をGNDに接続する一般的な配線を前提とする）
- 実機の配線がこれと異なる場合は、`InputManager`内の1箇所（読み取り論理の反転フラグ）を直すだけで済むようにする

### 3.6 チュートリアルの進行内容

2ステップ構成とする。

1. **ステップ1「うごかしてみよう」**: 壁を出さず、自機だけを表示。十字キー4方向すべてで一度ずつ動かすと（またはタイムアウトで）ステップ2へ自動的に進む
2. **ステップ2「壁に当たるとゲームオーバー」**: サンプルの壁1組を実際にスクロールさせ、自機が意図的にぶつかる（またはプレイヤーが動かなければ自然に当たる）と「ゲームオーバーの例です」という説明を表示し、キャンセルボタンでタイトルに戻る

いずれのステップも、キャンセルボタンでいつでもタイトルに戻れる。

### 3.7 タイトル画面の操作説明表現

- アイコン/ピクトグラムは自作アセットが必要になるため、初回実装では**テキスト表記**のみとする（`docs/development-guidelines.md`のスタイリング規約に従い、`M5GFX`の標準フォント描画のみで完結させる）
- 表示例: 画面下部2行に「[十字]うごく [OK]けってい」「[C]もどる」を固定表示する

### 3.8 設定・難易度選択の永続化

- 設定（しきい値）・難易度選択のいずれも**電源OFF後は保持しない**（`docs/product-requirements.md`のスコープ外方針＝ベストスコア等の永続保存を行わない、に合わせる）
- 起動時のデフォルトは「しきい値=中（MID）」「難易度=レベル1」とする

## 4. 影響範囲の分析

- `main.cpp`と`GUI.cpp`/`GUI.h`は全面的に書き換わるが、既存のタッチ読み取り・キャリブレーションの考え方（起動時に`touchRead()`で基準値を記憶する）はそのまま`InputManager`に引き継がれるため、動作確認済みのロジックを失わない
- 新規ファイルはいずれも他の既存機能に依存しないため、既存資産（`platformio.ini`のビルド設定等）への影響はない
- 本設計により`docs/product-requirements.md`・`docs/functional-design.md`の「未決事項」はすべて解消される
