# 物理ボタン実機テスト追加 要求内容（requirements.md）

対象: `.steering/20260926-add-button-hardware-test/`
参照元: `docs/architecture.md`, `docs/repository-structure.md`, `docs/development-guidelines.md`, `.steering/20260802-initial-implementation/`

## 1. 変更・追加する機能の説明

物理ボタン（G38=OK, G39=キャンセル）の配線不良を基板側で修正した。その修正が正しく効いていることを実機（AtomS3）上で確認するため、PlatformIO Unit Testing（Unity）による実機テストを `test/` 配下に追加する。

テスト対象:

1. ピンレベルの確認: 各ボタンが未押下時にLOW、押下時にHIGHになる（INPUT_PULLDOWN前提）
2. `InputManager` 経由の確認: 各ボタンを押すと `okPressed()` / `cancelPressed()` が押した瞬間だけtrueになる（エッジ検出・デバウンス込み）
3. 独立性の確認: 一方のボタンを押したときに、もう一方のボタンが反応しない（配線の短絡・取り違えがない）
4. 未押下時の安定性: 一定時間ボタンに触れない間、誤検出（ノイズによるHIGH・エッジ）が発生しない

テストは人がボタンを押す必要があるため、画面とシリアルに「どのボタンを押す／離すか」を指示し、制限時間内の入力を待って自動で合否を判定する形式とする。

## 2. ユーザーストーリー

- 開発者として、基板修正後に `pio test` を実行し、画面の指示に従ってボタンを押すだけで、配線修正が正しいか合否で確認したい
- 開発者として、テスト失敗時にどのボタンのどの観点（ピンレベル／エッジ検出／取り違え／ノイズ）で失敗したかをシリアル出力で知りたい

## 3. 受け入れ条件

- [ ] `pio test -e m5stack-atoms3` でテストがビルド・書き込み・実行される
- [ ] 画面とシリアルの指示に従ってボタンを操作すると、配線が正常な基板で全テストがPASSする
- [ ] ボタンを押さずに制限時間が過ぎた場合、該当テストがFAILし、原因が分かるメッセージが出力される
- [ ] 既存のアプリ本体（`src/`）の動作・ビルド（`pio run`）に影響しない
- [ ] `docs/development-guidelines.md` の命名規則・コーディング規約に沿っている

## 4. 制約事項

- 暫定対応（右タッチ=OK、設定・難易度選択の上下操作／縦並び表示）は今回は戻さない。戻す作業は本テストで配線修正を確認した後、別のステアリング作業として行う
- テストは実機専用とし、PC上で動くnative環境のテストは今回のスコープ外とする
- `InputManager` はタッチも同時に読むため、テスト実行中はタッチパッドに触れない前提とする
- `docs/development-guidelines.md`「4. テスト規約」と `docs/repository-structure.md` では `test/` の利用を「スコープ外」としているため、本作業に合わせて該当箇所を更新する
