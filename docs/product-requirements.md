# プロダクト要求定義書（product-requirements.md）

## 1. プロダクトビジョンと目的

M5Stack AtomS3 単体で完結する、タッチセンサーを使った「イライラ棒」風ミニゲームを開発する。
物理的なワイヤーではなく、AtomS3の静電容量式タッチセンサー（GPIO5〜8）を十字キーとして扱い、画面上に表示した迷路コースをカーソルで操作して壁に触れずにゴールを目指す。

- タッチ操作による方向入力という制約（アナログ的で反応がブレやすい）を活かし、「思い通りに操作できないイライラ感」自体をゲーム性として楽しむ。
- 既存の動作確認用プログラム（`main.cpp` / `GUI.cpp`）で得られたタッチセンサーの反応（`touchRead`の値の変化）を土台に、ゲームロジックを追加する。

## 2. ターゲットユーザーと課題・ニーズ

- **想定ユーザー**: AtomS3を持っている個人開発者・電子工作愛好家（自分自身）。展示・デモや友人・同僚へのちょっとした余興としての利用も想定。
- **課題・ニーズ**:
  - タッチセンサーだけで方向入力ができる、物理ボタンを使わない小型ゲームがほしい。
  - AtomS3の小さな画面でも完結する、単純明快な操作・ルールのゲームがほしい。
  - タッチセンサーの感度差・個体差があっても遊べる調整のしやすさがほしい。

## 3. 主要な機能一覧

1. タッチセンサー4方向入力（上下左右）によるカーソル移動
2. 迷路コースの表示（AtomS3画面、128x128）
3. 壁接触判定（イライラ棒の「棒が輪に触れる」に相当）
4. クリアタイム計測・表示
5. 失敗（壁接触）回数のカウント・表示
6. ゲーム状態遷移（タイトル／プレイ中／クリア／失敗時のリスタート導線）
7. タッチセンサーのキャリブレーション（起動時に初期値を記憶する仕組み。既存main.cppに実装済みの考え方を踏襲）

> 以下は今回のスコープ外（別途要望があれば追加検討）：
> - ベストタイム・ベスト記録の永続保存（NVS/Preferences）
> - 音・LEDなどによる演出フィードバック
> - 複数コース・難易度選択

## 4. 成功の定義

- タッチセンサー4方向でカーソルを迷路内で自在に操作できる。
- 壁に触れたら失敗と判定され、リスタートできる。
- ゴールに到達したらクリアと判定され、クリアタイムが表示される。
- 実機（AtomS3）上で一連の流れ（開始→プレイ→失敗or クリア→リスタート）が安定して動作する。

## 5. ビジネス要件

個人の学習・趣味目的のプロジェクトであり、商用要件・収益化要件は設定しない。

## 6. ユーザーストーリー

- プレイヤーとして、電源を入れたらすぐにゲームを開始したい。
- プレイヤーとして、十字キー（タッチ）でカーソルを直感的に動かしたい。
- プレイヤーとして、壁に触れたら失敗したことがすぐに分かるようにしたい。
- プレイヤーとして、ゴールしたら自分のクリアタイムを確認したい。
- プレイヤーとして、何度も壁に触れてしまった場合、その回数を確認して次のプレイの目標にしたい。
- プレイヤーとして、失敗してもすぐにリトライしたい。

## 7. 受け入れ条件

- [ ] GPIO5〜8のタッチセンサーそれぞれが上下左右いずれかの方向入力として機能する
- [ ] 起動時にタッチセンサーの初期値（未接触状態の基準値）を記憶し、個体差・環境差を吸収する
- [ ] 画面に迷路コース（壁）とカーソル、スタート/ゴール位置が表示される
- [ ] カーソルが壁に接触したら「失敗」と判定され、失敗回数が加算される
- [ ] カーソルがゴールに到達したら「クリア」と判定され、クリアタイムが表示される
- [ ] プレイ中はスタートからの経過時間が計測される
- [ ] 失敗・クリア後、リスタート操作でコース最初からやり直せる

## 8. 機能要件

- タッチ値の読み取り: `touchRead()`でGPIO5(G5)/6(G6)/7(G7)/8(G8)の4ピンを周期的に読み取る
- 方向判定: 起動時のキャリブレーション値から一定閾値以上の変化があったチャンネルを「入力あり」と判定する
- カーソル移動: 入力ありと判定された方向に、コース上の壁を考慮してカーソル座標を更新する
- 衝突判定: カーソルが壁領域と重なったら失敗状態に遷移する
- ゴール判定: カーソルがゴール領域に到達したらクリア状態に遷移する
- タイマー: プレイ開始時刻から経過時間をミリ秒単位で計測し、画面に秒単位で表示する
- カウンタ: 失敗（壁接触）回数を保持し、画面に表示する
- 画面描画: 128x128のAtomS3画面にコース・カーソル・タイム・失敗回数を表示する

## 9. 非機能要件

- 対象ハードウェア: M5Stack AtomS3（ESP32-S3、画面128x128、タッチ対応GPIOはG5/G6/G7/G8）
- 開発環境: PlatformIO（board=`m5stack-atoms3`, framework=`arduino`）、ライブラリはM5Unified / M5GFX
- 操作応答性: タッチ入力からカーソル移動までの遅延が体感できるほど大きくならないこと（ループ周期は既存コードの100ms程度を基準に、ゲームとして違和感のない範囲に調整する）
- 個体差対応: タッチセンサーの感度は個体・環境（湿度、静電気等）で変動するため、閾値は固定値決め打ちにせず調整しやすい構造にする
- 保守性: `GUI`クラスなど既存の責務分割（入力読み取り／ゲームロジック／描画）を維持・拡張する

## 10. 未決事項（次のドキュメントで検討）

- コース（迷路）データの作り方: 固定1コースで確定。データ形式（グリッド配列 / 座標リスト等）は`functional-design.md`で設計する
- 壁接触時の挙動の詳細: その場で失敗表示してリスタート待ちにするか、即座に自動リスタートするか
- 十字キー4入力の閾値・キャリブレーション方式の具体仕様
